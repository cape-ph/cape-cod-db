# Development workflow and tooling

## Prerequisites

- Python 3.10+, Poetry 2.3+, PostgreSQL 18.x for local dev.
- Optional: mise or asdf for tool versions. `.mise.toml` pins python 3.10,
  poetry 2.3, pre-commit 3, and opencode. `poetry.toml` sets in-project `.venv`.
- Install with `poetry install`.
- A `.env` file at repo root provides `DB_URL` and `LOG_LEVEL`. `.env` is
  gitignored; never commit credentials.

## Quality checks

Run before considering work complete (also in the project completion checklist):

```bash
poetry run ruff check cape_cod_db/
poetry run pyright
```

- Ruff: line length 80, `extend-exclude = ["cape_cod_db/migrations"]`. Format
  with `poetry run ruff format cape_cod_db/`.
- Black: line length 80, force-excludes `cape_cod_db/migrations`.
- isort: black profile, line length 80, skips migrations.
- Pyright: `basic` type-checking mode, ignores `cape_cod_db/migrations/**` and
  `dist/**` (see `pyrightconfig.json`).

The migrations directory is deliberately excluded from formatters/linters
because it is autogenerated.

## Pre-commit hooks

`.pre-commit-config.yaml` runs standard pre-commit-hooks (trailing whitespace,
mixed line ending, check-yaml, check-toml, check-merge-conflict), Black, isort,
and typos. It excludes `^notes/` (a legacy path; see below).

## Conventions

- Type hints use 3.10+ union syntax (`int | None`).
- All tables inherit `CapeModel` (except the `UserTributary` join table); see
  [[concepts/capemodel-base-class]].
- Never bypass Alembic for schema changes on tracked databases.
- Register new models in `migrations/env.py`.
- No PII/PHI in logs (the `User.__repr__` PII TODO is still open); no
  credentials in code.
